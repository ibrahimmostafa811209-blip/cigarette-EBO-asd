# 🚬 مدير محل السجائر (Cigarette Shop Manager)

تطبيق ويب (PWA) بسيط لإدارة محل سجائر: بيع (كاشير)، منتجات، مخزون، مصروفات، تقارير، نسخ احتياطي. يعمل بدون إنترنت بعد أول فتح، وبدون أي برامج أو إعدادات.

## الملفات
```
cigarette/
├── index.html      الصفحة الرئيسية (لازم تكون في الجذر)
├── app.js          كل منطق التطبيق
├── style.css       التصميم (عربي RTL)
├── sw.js           للعمل بدون إنترنت
├── manifest.json   لتثبيت التطبيق على الموبايل
├── icon.svg / icon-192.png / icon-512.png
├── .nojekyll       يمنع GitHub من تشغيل Jekyll
└── README.md
```

## أول استخدام
- المستخدم: `admin` — كلمة المرور: `admin123` — هيطلب منك تغييرها فورًا.
- من «المستخدمين» أضف حسابات الكاشير. من «المنتجات» أضف الأصناف (أو من الإعدادات أضف بيانات تجريبية).

## الرفع على GitHub من الموبايل
1. افتح github.com من المتصفح وسجّل دخول (يفضّل «Desktop site» من قائمة المتصفح).
2. اضغط **+** ← **New repository**. الاسم: `cigarette`. اختر **Public**. اضغط **Create repository**.
3. في صفحة المستودع اضغط **uploading an existing file** (أو Add file ← Upload files).
4. اختار كل الملفات من ملف ZIP بعد فكّه (لازم `index.html` يكون في الجذر وليس داخل مجلد). لا تنسَ `.nojekyll` (لو الموبايل يخفي الملفات التي تبدأ بنقطة، أنشئه من Add file ← Create new file واكتب اسمه `.nojekyll` واحفظ).
5. اضغط **Commit changes**.

## تفعيل GitHub Pages
1. من المستودع: **Settings** ← **Pages**.
2. تحت Source اختر **Deploy from a branch**.
3. Branch: **main** — Folder: **/(root)** ← **Save**.
4. استنى 1–3 دقائق، الرابط هيظهر: `https://USERNAME.github.io/cigarette/`.
5. افتح الرابط على الموبايل ← قائمة المتصفح ← **Add to Home screen / تثبيت التطبيق**.

## حل المشاكل
- **404**: تأكد أن `index.html` في الجذر مش داخل مجلد، وأن Pages على main و /(root)، وأن اسم الرابط يطابق اسم المستودع بالحروف.
- **صفحة بيضاء**: تأكد أن `app.js` و `style.css` مرفوعين وأسماؤهم بنفس الحروف الصغيرة.
- **Deploy فشل**: افتح تبويب **Actions** وشوف الخطأ. تأكد من وجود `.nojekyll` وعدم وجود ملفات SCSS أو `_config.yml`.
- **تحديث لا يظهر**: افتح الصفحة، اسحب للتحديث، أو امسح كاش الموقع (البيانات في IndexedDB — خد نسخة احتياطية قبل مسح أي شيء).
- **ضاعت البيانات**: استعد من ملف النسخة الاحتياطية (الإعدادات ← استعادة).

## المعادلات (كل المبالغ بالقروش كأعداد صحيحة)
- **الإيراد** = Σ (سعر البيع × الكمية − الخصم الموزّع على البنود).
- **تكلفة البضاعة المباعة** = Σ (سعر الشراء وقت البيع × الكمية) للبنود المسجّل لها تكلفة فقط.
- **إجمالي الربح** = إيراد البنود ذات التكلفة − تكلفتها. (لا يتم تخمين تكلفة غير مسجلة.)
- **صافي الربح التقديري** = إجمالي الربح − المصروفات.
- التدفق النقدي ليس هو الربح المحاسبي.

## حدود أمنية (مهم)
- تسجيل الدخول والصلاحيات تعمل داخل المتصفح فقط، وليست حماية حقيقية: أي شخص عنده خبرة وجهاز المحل يقدر يقرأ/يعدّل البيانات من أدوات المتصفح. كلمات المرور تُخزَّن مُجزّأة (SHA-256 بملح) محليًا فقط.
- البيانات محفوظة على نفس الجهاز/المتصفح، **لا تتزامن** بين الأجهزة. مسح بيانات المتصفح أو حذف التطبيق يضيعها. خد نسخة احتياطية بانتظام.
- ملف النسخة الاحتياطية يحتوي على بيانات المستخدمين (مُجزّأة) — احفظه في مكان آمن.
- لا يوجد: تعدد أجهزة حقيقي، صلاحيات على الخادم، سجل تدقيق غير قابل للتعديل.
- للمستقبل: خادم (API) + قاعدة بيانات (مثل PostgreSQL) + مصادقة حقيقية (جلسات/JWT وتجزئة bcrypt/argon2) + صلاحيات على الخادم + مزامنة. نقطة الدمج: الكائن `DB` في أول `app.js` (get/put) ودوال الدخول `loginView/hash`.
